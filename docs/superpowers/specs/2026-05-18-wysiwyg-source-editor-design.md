# WYSIWYG Source Editor for the Annotator

**Date:** 2026-05-18
**Status:** Approved — ready for implementation planning

## Context

The annotator page (`app/_static/annotator.html`) currently provides "Edit Source" as a plain `<textarea>` next to the preview iframe. No syntax highlighting, no inline rendering, no formatting shortcuts — just monospace text. The reference WYSIWYG editor in `supernova-agents-framework/web` (`components/milkdown-editor.tsx`) demonstrates a much better experience using Milkdown Crepe: headings, bold, lists, tables, and links render in place as you type, with floating toolbars and image paste support.

This spec replaces the textarea with a Milkdown Crepe editor, matching the reference's behavior.

## Goal

When the user clicks "Edit Source" in the annotator, they get a Typora-style WYSIWYG editor mounted in the source pane — same panel position, same save/reload buttons, same socket plumbing — but with inline rendering of all CommonMark+GFM constructs the reference supports.

## Non-goals

- No raw-source toggle (a previous "hybrid" option was explicitly rejected)
- No Latex/math editing inside the editor (preview iframe still renders math)
- No slash menu (`BlockEdit` feature) — can be added later
- No new socket events; reuse `read_source` / `write_source`
- No changes to the preview iframe rendering pipeline
- No changes to the annotation/highlight system on the preview side

## Architecture

The annotator stays vanilla HTML/JS. Milkdown ships as a single pre-built IIFE bundle loaded lazily on first source-edit toggle. The bundle exposes one global, `window.MdpAnnotatorEditor`, with a small lifecycle API the annotator's existing JS drives.

```
app/
  annotator-editor/          ← new (TypeScript source for the bundle)
    index.ts                 ← Crepe setup, exposes window.MdpAnnotatorEditor
    image-compress.ts        ← port of reference's lib/image-compress
    styles.css               ← design-token overrides matching annotator.html's cream theme
  _static/
    annotator.html           ← modified: textarea → mount div, lazy-load bundle
    milkdown.bundle.js       ← generated by esbuild, committed to repo
    milkdown.bundle.css      ← generated by esbuild, committed to repo
```

### Why pre-bundle (not CDN)

`markdown-preview.nvim` is installed via vim plugin managers; users may be offline. The existing build chain in root `package.json` already produces shipped artifacts (`pkg --targets …`). Adding an esbuild step that runs at release time keeps end-user installs zero-toolchain.

## Bundle API

```ts
window.MdpAnnotatorEditor.create({
  root: HTMLElement,
  initialValue: string,
  onChange: (markdown: string) => void,   // fires on user edits only
  readOnly?: boolean,
}) => {
  replaceContent: (markdown: string) => void,  // for Reload + file switch — does NOT fire onChange
  getMarkdown: () => string,
  setReadonly: (readonly: boolean) => void,
  destroy: () => void,
}
```

The `suppressNextChangeRef` pattern from the reference (`milkdown-editor.tsx:50`) prevents reload-induced echoes from triggering autosave. We port that exact pattern.

## Crepe configuration (mirrors the reference)

Disabled features:

| Feature      | Reason |
|--------------|--------|
| `CodeMirror` | We don't need an in-editor code-block editor; fenced blocks stay as opaque text |
| `ImageBlock` | We handle images via the `uploadConfig` override (data: URLs) |
| `Latex`      | Round-trip risk; the preview iframe still renders KaTeX from the saved markdown |
| `BlockEdit`  | Slash menu — out of scope for v1 |
| `TopBar`     | The annotator has its own topbar |

Enabled (Crepe defaults): floating selection toolbar, link tooltip + edit UI, table cell handles, task list checkboxes, image paste/drop, list/heading/blockquote/HR inline rendering.

## Wiring changes in `annotator.html`

The socket plumbing (`read_source` / `write_source` / `sourceAutoSaveTimer` / `sourceSaving` flag / `sourceContentSnapshot`) stays. The textarea-specific bits change:

| Today (textarea) | After (Milkdown) |
|---|---|
| `<textarea id="sourceEditor" class="source-editor" …>` | `<div id="sourceEditor" class="source-editor"></div>` |
| `sourceEditor.value = content` | `editor.replaceContent(content)` |
| `sourceEditor.value` reads | `editor.getMarkdown()` reads |
| `sourceEditor.value === sourceContentSnapshot` checks | `editor.getMarkdown() === sourceContentSnapshot` |
| `sourceEditor.addEventListener('input', …)` | `onChange` callback wired into `create({ onChange })` |
| `sourceEditor.addEventListener('keydown', Cmd-S, …)` | listener attached to mount div instead |
| Plain `.source-editor` CSS (textarea styling) | Removed; bundle's CSS handles editor styling |

Lazy load: the first time `toggleSourceBtn` is clicked, inject `<script src="milkdown.bundle.js">` and `<link rel="stylesheet" href="milkdown.bundle.css">`, await the bundle, then construct the editor. Subsequent toggles just show/hide the pane.

The autosave/debounce timing (900ms after last edit), the Reload button, and the `keydown` Cmd-S save trigger all behave identically to today.

## Image paste

Port `compressImageFile` from the reference (`@/lib/image-compress` in the reference repo) and the `uploadConfig.uploader` override (`milkdown-editor.tsx:92-109`). When the user pastes or drops a raster image, the file is compressed client-side and embedded as a `data:` URL in the markdown. Non-raster types (SVG, GIF) pass through uncompressed.

This means saved files become self-contained — pasted images live inside the `.md` file, no separate asset directory needed.

## Round-trip behavior (documented trade-off)

Crepe is a ProseMirror-based editor: it parses markdown into a syntax tree on load, lets the user edit the tree, then serializes back to markdown. The serialized output is Crepe's canonical form, not the original byte sequence. Concretely:

- List markers may normalize (`*` → `-`)
- Trailing whitespace strips
- Link reference-style links may inline
- Heading underline syntax (`====` / `----`) may convert to `#` form
- Paragraph wrapping may change

Fenced code blocks (including mermaid, plantuml, dot, chart) pass through unchanged — Crepe treats them as opaque text nodes. The preview iframe continues to render them.

We accept this trade-off because it's exactly what the reference does, and the reference's editing experience is the stated bar.

## File-switch behavior

When the user switches to a different file in the file tree while the source pane is open, the existing flow already calls `loadSourceFromServer` after a 500ms delay (`annotator.html:1449`). With the new editor, this calls `editor.replaceContent(newSource)` instead of assigning to the textarea. Pending autosave from the previous file fires first (via the existing `sourceAutoSaveTimer`) — no change needed there.

If unsaved changes exist when switching, today's behavior is "autosave fires, then switch." This stays the same.

## Styling

The bundle's CSS uses CSS variables that map to the annotator's existing design tokens (cream/warm palette in `annotator.html:1-50`). Specifically:

```css
.milkdown-wrapper .milkdown {
  --crepe-color-background: var(--bg-surface);
  --crepe-color-on-background: var(--text);
  --crepe-color-surface: var(--bg-surface);
  --crepe-color-outline: var(--border);
  --crepe-color-primary: var(--accent);
  --crepe-color-hover: var(--bg-hover);
  /* etc. */
}
```

The reference's full style block (`milkdown-editor.tsx:155-643`) is the template — adapt the variable names from Shadcn (`--foreground`, `--card`, etc.) to the annotator's tokens (`--text`, `--bg-surface`, etc.).

## Build

Add to root `package.json`:

```json
"devDependencies": {
  "esbuild": "^0.20.0",
  "@milkdown/crepe": "^7.5.0",
  "@milkdown/core": "^7.5.0",
  "@milkdown/react": "^7.5.0",
  "@milkdown/plugin-upload": "^7.5.0",
  "@milkdown/exception": "^7.5.0",
  "@milkdown/prose": "^7.5.0"
},
"scripts": {
  "build-annotator-editor": "esbuild app/annotator-editor/index.ts --bundle --format=iife --target=es2020 --outfile=app/_static/milkdown.bundle.js --loader:.css=css --minify --global-name=MdpAnnotatorEditor"
}
```

(Pin exact versions during implementation against whatever the reference is on at the time.)

The existing `build` script gets `npm run build-annotator-editor &&` prepended.

The generated `milkdown.bundle.js` and `milkdown.bundle.css` are committed to the repo so users installing the vim plugin don't need a JS toolchain.

## Testing

- Manually verify each Crepe feature works: headings, bold/italic, lists (bullet/ordered/task), tables, blockquotes, fenced code, inline code, links (paste-to-link, edit, follow), images (paste, drag)
- Round-trip test: load a real markdown file from the repo (e.g., `README.md`), edit a bit, save, diff — confirm only expected normalizations happen
- File-switch with unsaved changes: confirm autosave fires before switch
- Lazy load: confirm bundle is not fetched until "Edit Source" is first clicked
- Cmd/Ctrl-S save: works from inside the editor
- Reload button: discards local edits, re-fetches from buffer
- Mermaid/plantuml fenced blocks: confirm they're preserved verbatim through edit+save
- Preview iframe still re-renders math/diagrams from the saved markdown

## Out of scope (deferred)

- Slash menu (`BlockEdit` feature)
- Inline Latex editing
- Multi-file find/replace
- Outline/TOC sidebar inside the editor
- Vim keybindings inside the editor (the annotator is intentionally browser-style)
